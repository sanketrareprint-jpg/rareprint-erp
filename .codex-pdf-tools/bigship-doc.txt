🔒 Authentication
All APIs (except login) require a valid Bearer Token in the request header:
Authorization: Bearer {token}
You can obtain this token by calling the User Login API.
🚦 API Rate Limiting
To maintain system performance and prevent abuse, rate limiting may be applied:
• Standard rate limit: 100 requests per minute per IP (can be customized based on integration
level)
• Exceeding limits may result in a 429 Too Many Requests error.
💰 Currency Format
All amounts (e.g., wallet balance, rates, invoice amounts) are in Indian Rupees (₹), not in paise.
Example: A balance of "1000.00" represents ₹1,000.00.

📄 Pagination Rules
When fetching paginated data from endpoints (e.g., warehouse list, drop locations list), follow the
rules below:
• The perPage value must be a multiple of 5.
• You can request a maximum of 25 records per page.
• If these rules are not followed, the API will respond with an appropriate error message:
o You can view up to 25 records per page at a time.
o You can get records in multiples of 5.
✅ Valid values for perPage: 5, 10, 15, 20, 25

1. API: User Login/Token Generation
Purpose: This endpoint allows users to log in to the system by providing their credentials. Upon
successful authentication, the API returns user-specific data along with a session token.
API Request:
• Method: POST
• URL: {{url}}api/outbound/login
Request Headers:
• Content-Type: application/json
Request Body:
The request body should be in JSON format and contain the following parameters:
• username (string, required): The email address of the user.
• password (string, required): The password associated with the user's account.
• access_key (string, required): A key used for additional access control.
Sample Request Body:
{
"username": "your_email@example.com",
"password": "your_password",
"access_key": "your_access_key"
}
Response Structure:
This information is crucial for managing user sessions and accessing user-specific data within the
application.
On a successful login, the API responds with a JSON object that includes the following keys:
• status (boolean): Indicates whether the login was successful.
• message (string): A message providing additional information about the login attempt.
• status_code (integer): The HTTP status code of the response.
• data (object): Contains user-specific information, including:
o firstName (string): The first name of the user.
o lastName (string): The last name of the user.
o EmailID (string): The email address of the user.
o mobileNumber (string): The mobile number of the user.
o countryname (string): The name of the country associated with the user.
o IsEmailVerifed (boolean): Indicates whether the user's email has been verified.
o token (string): The session token for the authenticated user.
o tokenExpiringAt (string): The expiration time of the session token.

2. API: Get Profile

API Request:
• Method: GET
• URL: {{url}}api/outbound/profile
Request Headers:
• Content-Type: application/json
• Authorization: Bearer Token
Request Body: No body or parameters are required for this GET request.

2. message (string): A message related to the response.
3. status_code (integer): The HTTP status code of the response.

c. EmailID (string): The email ID associated with the profile.
d. mobileNumber (string): The mobile number associated with the profile.

containing the following keys:

ii. access_key_generated_date (string): The date when the access key was
generated.

iv. created_date (string): The date when the account was created.
v. updated_date (string): The date when the account was last updated.
i. userWallet (object): The user's wallet information containing the following keys:
i. Balance (string): The current balance in the wallet.
ii. kycCurrency (string): The currency used for KYC.

3. API: Save Warehouse API (Save Pickup Location Data)
Purpose: This API endpoint is used to save warehouse data for logistics operations.
API Request:
• Method: POST
• URL: {{url}}api/outbound/save-warehouse-data
Request Headers:
• Content-Type: application/json
• Authorization: Bearer Token
Request Body:
The request body should be in JSON format and contain the following parameters:
• segment_type (text, required): The type of segment (e.g., hyperlocal, local).
• warehouseContactPerson (text, required): The contact person at the warehouse.
• warehouseAddressPhone (text, required): The phone number of the warehouse.
• warehouseCountry (text, required): The country where the warehouse is located. It must be
India when segment_type is hyperlocal or local.

-- 8 of 33 --

• warehouseState (text, required): The state where the warehouse is located.
• warehouseCity (text, required): The city where the warehouse is located.
• warehousePinCode (text, required): The pin code of the warehouse.
• warehouseAddressLine1 (text, required): Primary address of the warehouse. Must contain a
minimum of 3 words and a maximum of 75 words.
• warehouseAddressLine2 (text, optional): Secondary address of the warehouse. Must
contain a minimum of 3 words and a maximum of 75 words.
• warehouseAddressLandMark (text, required): Landmark near the warehouse. Must contain
a minimum of 3 words and a maximum of 50 words.
• latitude (text, required): The latitude of the warehouse. Only required when segment_type
is hyperlocal.
• longitude (text, required): The longitude of the warehouse. Only required when
segment_type is hyperlocal.
• address_type (text, required): Specifies the type of address. This field is required only when
segment_type is hyperlocal. Allowed values are: Home, Office, Shop, Factory, Hotel, Other.

o warehouseId: The ID of the warehouse where the data was saved.
